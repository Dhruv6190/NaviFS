Engine Architecture

Engineered for Determinism and Zero Context Waste

Eliminating hallucination, token explosion, and unbounded file dumps with strict index-backed context budgeting.

< 10ms

Three-Channel Hybrid Retrieval & Rank Fusion

Combines Channel A (SQLite FTS5 lexical BM25 matching), Channel B (path hierarchy scoping), and Channel C (dense vector cosine similarity via offline BGE-small embeddings on Candle). Merged with Reciprocal Rank Fusion (RRF k=20.0) and refined through a 4D feature reranker.

RRF(d) = Σ [ w_c / (k + rank_c(d)) ] | k = 20.0 rerank_score = (0.45 * lexical) + (0.25 * path) + (0.15 * freshness) + (0.15 * quality)
0 Tokens

Bounded Content Range Retrieval

Never dump whole files into LLM context. The open tool retrieves exact byte, line, or page slices with unique resource URIs and evidence locators.

100% Embedded

Zero-Mock SQLite Storage

Pure local SQLite with WAL mode, foreign key cascades, and automated FTS5 triggers for instant incremental synchronization on file insert, update, or rename.

Native Rust

Streaming Multi-Format Document Parsers

Pure Rust streaming decoders without Python or external server overhead. Extracts text streams, headings, and cell tables directly from PDF (FlateDecode), Excel spreadsheets (XLSX/XLS/ODS via calamine), Word documents (DOCX via OpenXML), Markdown, and JSON.

Supported Formats: .rs .py .ts .js .md .json .pdf .xlsx .xls .docx .txt .csv

Documentation / Overview

NaviFS Overview

NaviFS is a high-throughput, local-first filesystem intelligence engine and Model Context Protocol (MCP) server written in pure Rust.

Design Philosophy

Most LLM coding tools fail when confronting medium or large codebases because they either exhaust the context window by injecting thousands of lines of unverified text, or hallucinate filenames and signatures. NaviFS enforces a strict context budgeting model:

  • Two-Stage Candidate Generation: Never inspect files sequentially. Match candidates in parallel across FTS5 content, path indices, and vector embeddings.
  • Mathematical Rank Fusion: Local RRF ($k=20.0$) normalizes disparate scores and rewards cross-channel confirmation.
  • Bounded Retrievals: AI agents retrieve exact bounded ranges ($L_{10}-L_{40}$ or Page 3) rather than whole files.
  • Zero Mock Data: Every query is backed by real SQLite, real cryptographic SHA-256 hashes, and deterministic AST/stream parsers.
Specification Compliance
Built to strictly conform to the NaviFS Developer Handoff & Technical Design Specification (Baseline 2026-10-03) and the official Model Context Protocol (2024-11-05).

1-Click Plug & Play Installation

Install the pre-compiled NaviFS engine and automatically configure all your AI IDEs with zero manual configuration.

Quick Install

Run the 1-click installer for your operating system. It downloads the pre-built release binary, validates the SHA-256 checksum, places navifs in your program bin directory, adds it to your user PATH, and launches the interactive auto-configurator.

Windows (PowerShell)

# 1-Line Remote Installer:
powershell -ExecutionPolicy Bypass -Command "irm https://raw.githubusercontent.com/Dhruv6190/NaviFS/main/install.ps1 | iex"

# Or from local clone:
.\install.ps1 -All

macOS & Linux (Bash / Zsh)

# 1-Line Remote Installer:
curl -fsSL https://raw.githubusercontent.com/Dhruv6190/NaviFS/main/install.sh | bash

# Or from local clone:
./install.sh

Interactive Auto-Configurator

Once installed, run navifs setup at any time to connect newly installed AI agents or perform safe dry-runs and rollbacks: 

# Interactive terminal selection
navifs setup

navifs setup --all

# Inspect what would change without modifying files
navifs setup --dry-run --all

# Safely remove NaviFS from client configs
navifs setup --uninstall

# Target a specific client
navifs setup --client claude
navifs setup --client cursor
navifs setup --client antigravity
navifs setup --client windsurf
navifs setup --client vscode

search Tool (§7.2)

Hybrid retrieval combining SQLite FTS5, path/metadata filters, aggressive rank fusion, and feature vector reranking.

Input Parameters

Field Type Required Description
query string Yes Natural language query or code search keywords
filters object No Scoped filters: path_prefix, mime_types, modified_after, modified_before
limit integer No Maximum top-K candidates to return (default 10)

Three-Channel Retrieval Mechanics

The search tool executes candidate generation across three distinct channels simultaneously:

  • Channel A (Content Lexical): SQLite FTS5 full-text matching with BM25 ranking across tokenized content chunks.
  • Channel B (Path & Hierarchy): Token-based path segment matching rewarding exact filenames and target directories.
  • Channel C (Semantic Vector): 384-dimensional dense vector embeddings generated via pure-Rust Candle (BGE-small-en-v1.5) compared via L2-normalized cosine similarity.

open Tool (§7.5)

Bounded content range retrieval by lines, pages, byte offsets, or chunk index with deterministic index locators and resource URIs.

Zero Token Explosion Architecture

AI agents frequently crash context windows when attempting to read large files. The open tool enforces strict bounded retrieval. It accepts either line intervals, page boundaries (PDF), byte slices, or exact chunk IDs.

Parameters

Field Type Required Description
file_id string (UUID) Optional* Unique file identifier (*Either file_id or path required)
path string Optional* Relative or absolute filesystem path
start_line integer Optional 1-indexed starting line number of the bounded range
end_line integer Optional 1-indexed ending line number of the bounded range
start_page integer Optional 1-indexed starting page number (for PDF documents)
end_page integer Optional 1-indexed ending page number (for PDF documents)
byte_start integer Optional Physical starting byte offset
byte_end integer Optional Physical ending byte offset
chunk_index integer Optional Sequential chunk number within the file

inspect Tool (§7.4)

Generates structural metadata summaries, chunk metrics, worksheet/heading taxonomy, and recent temporal event history.

Structural Discovery

The inspect tool enables an agent to survey an entire document's shape before consuming any chunk content:

  • Spreadsheets (XLSX, XLS, ODS): Discovers all worksheet names (e.g. ["UAE Leads", "Contacts", "Revenue"]).
  • Word & Markdown (DOCX, MD): Lists hierarchical sections and heading titles.
  • Source Code (Rust, Python, TS): Outlines extracted AST classes, structs, traits, and functions.
  • Temporal Audit History: Returns the last 10 lifecycle events (created, modified, indexed, deleted) with timestamps.

related Tool (§7.6)

One-to-one hop knowledge graph traversal discovering adjacent nodes, directional relation edges, and relation weights.

Knowledge Graph Traversal

NaviFS builds an in-memory and SQLite-backed directional property graph connecting files, sections, code AST entities, and worksheets. The related tool returns both incoming and outgoing edges for any center node.

Supported Relationship Types

Relation Type Direction Semantics
Contains Parent -> Child File contains worksheet, heading section, or struct
References Source -> Target Document cites or references another document path
Imports Source -> Target Source file imports module or external dependency
Defines File -> Entity File declares a function, class, type, or schema

System & Crates Architecture (§5)

Detailed technical overview of the 9 modular workspace crates comprising NaviFS.

Crate Role & Key Responsibilities
crates/core Domain identity, FileId, ChunkId, ByteRange, LineRange, MimeType, Embedder trait, Result types
crates/database Embedded SQLite, WAL mode, foreign keys, migrations 0001-0003, FTS5 sync triggers, embedding BLOB storage
crates/extract Multi-modal parsers: PDF, XLSX (calamine), DOCX (quick-xml), Markdown, JSON, plain text
crates/embed Local sentence embeddings (BGE-small-en-v1.5, 384-d) on pure-Rust Candle; zero external DLLs, offline cached
crates/search 3-channel hybrid retrieval (Content FTS5 + Path + Vector similarity), RRF (k=20), 4D Feature Reranker
crates/graph In-memory bidirectional adjacency index and BFS traversal
crates/indexer Directory scanner (WalkDir), debounced watcher with SHA-256 verification, batch vector embedding
crates/mcp JSON-RPC 2.0 stdio server, tool dispatcher, MCP 2024-11-05 standard schemas
crates/daemon CLI binary entrypoint: daemon, scan, search, mcp stdio mode, and atomic AI client setup

Automated SQLite FTS5 Synchronization

NaviFS uses database-level triggers to keep full-text indices perfectly synchronized with zero application latency. When content chunks are inserted, updated, or deleted, triggers automatically update the FTS5 virtual table.

Temporal Intelligence (§13 & §17.1)

Persistent audit logging and time-travel query support for file lifecycle events.

Event Lifecycle State Machine

NaviFS tracks physical and logical file mutations through persistent SQLite event logging:

  • created: Emitted when a new file path is discovered by the initial scanner.
  • modified: Emitted when the OS notify watcher triggers and SHA-256 content verification detects changes.
  • indexed: Emitted when multi-modal extraction succeeds and chunks/entities are written to SQLite.
  • deleted: Emitted when a file is purged from disk, cascading deletion across chunks and FTS5.

Evaluation Harness (§22)

Golden benchmark suite verifying retrieval precision, latency, and automated MCP tool trace workflows.

Running the Benchmark Suite

# Execute full evaluation harness
cargo run -p navifs-eval --release

# Run automated MCP tool trace integration test
cargo test -p navifs-eval --test trace_test

The evaluation harness seeds a multi-format synthetic filesystem (Rust code, Markdown docs, JSON configurations, PDF reports, and Excel spreadsheets), runs standard queries, and measures Precision@K, Recall@K, Mean Reciprocal Rank (MRR), and end-to-end P99 latency.
